# Mac 智能清理脚本

智能扫描 macOS 上可清理的内容，自动区分「可直接删除」和「需用户判断」两类，并在**用户确认后**才真正删除，避免误删用户数据。

- 脚本路径: `scripts/mac-clean/smart-clean.sh`
- 设计参考: `docs/mac-clean-plan.md`

## 用法

```bash
# 仅扫描并列出可清理项（推荐先跑这个）
smart-clean.sh --list

# 进入交互确认模式（默认）
smart-clean.sh --clean

# 自动删除所有[安全]项；[需判断]项仍会逐个询问
smart-clean.sh --yes

# 查看帮助
smart-clean.sh --help
```

| 参数 | 行为 |
|------|------|
| `--list` | 只扫描、计算大小并列出两类清单，**不删除任何内容** |
| `--clean` | 打印清单后进入交互确认，每个项目都需确认 |
| `--yes` | 自动清理所有 [安全] 项，[需判断] 项仍提问 |

## 输出分类

| 类型 | 含义 | 默认处理 |
|------|------|---------|
| **■ [安全]** | 可再生缓存 / 临时文件 / 崩溃转储，删除无风险 | `--yes` 自动删，`--clean` 逐项确认 |
| **■ [需判断]** | 可能含用户数据、正在使用、删除后需重装 | 始终需用户确认 |

只有占用 **≥ 10MB** 的项目才会被列出；**≥ 200MB** 的全局 npm 包 / ≥ 500MB 的项目 `node_modules` 才会单独标记。

## 扫描范围

### [安全] 项（可再生缓存）
- `~/Library/Caches`（用户应用缓存）
- `~/Library/Logs`（用户日志）
- `~/.npm`、`~/.cache/node-gyp`、`~/Library/Caches/pip`（包管理器缓存）
- Homebrew 下载缓存（`brew --cache`）
- Xcode DerivedData、CoreSimulator 缓存
- JVM/IDE 崩溃转储 `*.hprof`
- `/cores` 核心转储（仅当当前用户可写时）

### [需判断] 项
- `~/.cache/codex-runtimes`（未用 Codex 可删）
- `~/.cache/huggingface`（本地推理模型缓存）
- 全局 npm 大体积包（>200MB，如 `omniroute`）
- 项目级 `node_modules`（>500MB，删除需重装）
- `~/.Trash` 废纸篓
- `~/Downloads` 中 >200MB 的大文件
- 用户目录下 >1GB 的大文件（模型文件等）

## 工作机制

1. **扫描**：对每个候选路径调用 `du`/`stat` 计算字节占用，仅列出超过阈值者。
2. **分类**：命中安全模式（缓存/日志/转储）记为 `safe`，其余记为 `rev`（需判断）。
3. **展示**：分成两个清单打印，并汇总各自可释放的总空间。
4. **确认**：`--clean`/`--yes` 时先总体确认，再逐项确认；只有输入 `y` 才执行删除命令。
5. **复核**：删除后校验路径是否清空，残留时给出 ⚠ 提示（仅供提示，不做二次删除）。

## 安全性说明

- 默认只**列出**不删除；必须显式指定 `--clean` 或 `--yes` 才会真正执行。
- 所有删除命令通过 `eval` 拼接执行，路径均已加引号处理，避免含空格路径出错。
- `[需判断]` 项（如模型文件、`node_modules`、废纸篓）始终需要逐项确认，防止误删数据。
- 建议先运行 `--list` 查看，再决定执行 `--clean`。
- 对于系统级目录（如 `/Library/Caches`、`/var/log`），脚本当前不主动纳入（需要 sudo 且收益有限），仍可参考 `docs/mac-clean-plan.md` 手动处理。
